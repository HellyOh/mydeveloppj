# Day 1 — 터미널과 Git

학습일: 2026-10-08 (한국시간)

## 직접 작성한 학습 메모

> 파일 저장은 로컬에 저장하는것이고 GitHub 공유는 클라우드 환경에 올려 두는 것이다.

표현을 정확히 하면, 파일 저장은 현재 작업 환경의 파일을 바꾸는 것이고 GitHub 공유는 커밋을 GitHub의 원격 저장소로 전송하는 것이다.

여기서 '로컬'은 Git 명령을 실행하는 현재 환경을 말한다. 현재는 Codex 클라우드 환경이다. Codex 클라우드의 파일 저장과 GitHub 원격 저장소의 변경은 서로 별개의 작업이다.

## 확인한 개념

- `pwd`: 현재 작업 중인 폴더의 경로를 표시한다.
- `git status --short`: 파일의 Git 상태를 짧게 표시한다.
- `M`: Modified, 수정된 파일을 뜻한다.
- 파일을 저장하는 것만으로 GitHub에 변경이 반영되지는 않는다.
- `git add`: 현재 파일 내용을 다음 커밋에 포함할 대상으로 준비한다. 이 단계를 스테이징이라고 한다.
- `git commit`: 준비한 변경을 현재 환경의 Git 이력에 기록한다.
- `git push`: 커밋을 GitHub의 원격 저장소로 전송한다.

## 이번 실습

사용자가 작성한 문장을 이 파일에 저장했다. 다음 명령으로 이 메모를 스테이징하고 전후의 상태를 비교한다.

```bash
git status --short -- notes/day01-git.md
git add -- notes/day01-git.md
git status --short
```

- 새 파일을 아직 스테이징하지 않았을 때: `?? notes/day01-git.md`.
- 새 파일을 스테이징했을 때: `A  notes/day01-git.md`.
- 짧은 상태 표시의 첫 번째 칸은 스테이징 상태이고, 두 번째 칸은 작업 파일의 변경 상태다.
- 기존 파일이 수정된 ` M PROGRESS.md`와 새 파일이 스테이징된 `A  notes/day01-git.md`를 구분한다.

현재 학습 단계는 스테이징 전후 비교다. 메모의 커밋과 푸시는 다음 단계에서 확인한다.
